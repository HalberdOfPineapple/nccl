Store Congestion Data Paths

Where the bytes go when a store-only copy runs next to a local writer. The copy computes its values in registers and stores them to the destination GPU. The writer stores to a local 1 GiB buffer on its own SMs. Each diagram runs from the SMs at the top to HBM at the bottom.

Writer on the source GPU (E7.3)

Both flows leave SMs of the same GPU and enter its crossbar. There they split: peer stores go to the NVLink unit and local stores go to L2 and HBM. They use different GPCs here, so they can meet only in the crossbar.

Writer on the destination GPU (E7.7)

The copy is unchanged. The writer moves to the same SM IDs on the destination GPU, so the incoming peer stores and the local stores are written into the same L2 and HBM. This is the only test in the plan where both flows need the same memory. The copy changed by at most 0.29%; at no limit the writer lost 10.3%.

How a transfer finishes

  1. Every copy thread runs a system fence after its last store.
  2. Each copy CTA writes a "done" flag into destination memory, on the same path as the stores.
  3. The receiver CTA reads every flag, then writes an acknowledgement over NVLink into source memory.
  4. Each copy CTA reads the acknowledgement and records its end time. In E7.7 the writers stop after the acknowledgement.

How to read these diagrams

Not shared

SMs, their L1 caches and registers. Each role has its own SMs, one CTA per SM.

Assumed, not measured

NVIDIA does not document how NVLink traffic moves inside a GPU, or whether a peer store passes through local L2. The drawing shows the usual picture.

Rates

Write rates count requested bytes. With the writer alone, DRAM counters match them within about 0.2%; rates during the copy were not counted. L2 and HBM boxes stand for many slices and channels.
